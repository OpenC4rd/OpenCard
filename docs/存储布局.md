# OpenCard 存储布局

本文件规定 OpenCard 软件在用户机器上的持久化布局：什么东西放在哪里、哪一块可以删、路径由谁定义。

项目文件内部的持久化结构（`.ocdocument`、项目内部目录 `.opencard`）由 [工程规则](./工程规则.md) 负责；本文件只管软件自己的存储。

## 根

软件存储只有用户主目录下的一个根：`~/.opencard`。

- `~/.opencard` 是软件存储根，`<项目>/.opencard` 是项目内部目录。两者同名、层级不同、内容不相干；任何一方的路径都不得由另一方的常量拼出来。
- 软件存储不再有第二个根；历史上出现过的其他位置见文末，不再读写。
- webview 数据（`%LOCALAPPDATA%\<identifier>\EBWebView`）由系统和 Tauri 管理，不属于本布局，软件不得清理。
- 安装目录（Windows 上是 `%LOCALAPPDATA%\opencard`）属于发布物：`bundle.resources` 会把内置模板和内置包放到那里。它不属于用户存储，软件只读，不得清理或写入。

## 顶层条目

顶层是闭合集合，只有六项：

| 条目 | 内容 | 软件没运行时删掉会怎样 |
| --- | --- | --- |
| `settings.json` | 应用设置文档 | 设置回到默认值 |
| `update-state.json` | 已读的版本说明与待安装更新 | 更新提示再来一次 |
| `feedback-receipts.json` | 已提交的反馈与官方回复 | 反馈记录丢失 |
| `packages/` | 用户导入的附加包 | 附加包丢失 |
| `templates/` | 用户保存的项目模板 | 模板丢失 |
| `cache/` | 派生数据与暂存数据 | 没有任何损失 |

因此"哪块能删"只有一个答案：除 `cache/` 之外都装着你要的东西，`cache/` 随便删。

## 布局

```
~/.opencard/
├─ settings.json
├─ update-state.json
├─ feedback-receipts.json
├─ packages/
│  └─ <slug>.ocpack
├─ templates/
│  └─ <id>/
│     ├─ template.json
│     └─ content/…
└─ cache/
   ├─ packages/
   │  ├─ index.json
   │  └─ <sha256>/…
   ├─ network/
   │  ├─ index.json
   │  └─ <项目名>-<路径哈希>/<uid>.<ext>
   └─ staged/
      └─ <operationId>/<序号>-<文件名>
```

## 命名

- 目录名表达载荷身份，并且必须能从输入直接算出：解开的包用内容指纹 `<sha256>`，项目网络缓存用 `keySlug(项目目录名)-<规范化项目路径哈希前 8 位>`。不得引入"身份 → 目录名"的持久映射表：它只会随项目改名和移动而漂移，而缓存重新生成不需要任何代价。
- 同一个名字只表达一个意思。同一个 `cache.json` 在缓存里分别指项目映射和资源清单这类同名多义不得再出现。
- 簿记与被记录的对象放在一起，不平级并列：每种缓存一个 `index.json`，位于该缓存的目录内。
- 缓存条目目录内不写簿记：解开的包目录必须只包含包自己的文件，因此包缓存和网络缓存的 `index.json` 都放在各自的集合根，而不是放进每个条目目录。
- `index.json` 记录每个条目的最后使用时刻与占用字节数；清理时直接读它，不递归遍历目录树。
- 一个文档一个文件，文件内的键属于持久化协议：改键必须按 [命名规范](./命名规范.md) 单独规划读写两端，不得借布局调整顺手改。

## cache 规则

- 软件运行时 `cache/` 是活的：`cache/staged` 里的字节正是撤销要恢复的内容，此时删它会破坏撤销。
- 软件没运行时删 `cache/` 没有任何损失：派生数据下次用到会重建，`cache/staged` 里的字节在重启后已经没有任何入口能访问。
- 启动维护一次：清空 `cache/staged`；按 `index.json` 里的最后使用时刻对 `cache/packages` 和 `cache/network` 分别做 LRU 淘汰，直到各自不超过自己的字节上限（包缓存 2 GB，网络缓存 1 GB）；`index.json` 读不出来或载荷目录已不存在只影响清理顺序，不得阻止缓存使用。
- 进程被强杀时留在 `cache/staged` 的字节，随下次启动清掉。撤销栈本来就不跨进程，这是明确接受的代价。
- 解压到一半的目录以 `.` 开头（指纹永远是十六进制，两者不会相撞），启动时直接删。

## 路径归属

- `opencard-app/src/shared/storage/appStoragePaths.ts` 是软件存储路径的唯一出口：根名和每个顶层条目名只在这里出现。
- Rust 侧不得自己拼 `.opencard`：命令接受前端传入的绝对路径，需要安全前缀校验时使用传入的缓存根。
- 一个 spec 断言顶层条目恰好是上表六项；新增顶层条目必须同时改这个文件和本文件。
