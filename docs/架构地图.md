# OpenCard 架构地图

> 给人和 agent 共用。新增代码前先对照本页；`npm run lint:arch` 会强制其中的边界规则。
> 存量违规记录在 `opencard-app/scripts/architecture-baseline.json`，只许减少。

## 1. 依赖方向（只能向下依赖）

```
shell ─────────┐
card-designer ─┤→ workspace ─→ card-rendering ─→ entities
components/editors ┘              (纯核心)        (领域模型)
                        shared/ui、shared/model 可被任何层使用，但不得反向依赖 features
```

目标状态（尚未达成，见基线里的 `rendering-below-workspace`）：
`card-rendering` 不 import `workspace`；资源能力由 `workspace` 实现 `RenderResourcePort` 后注入。

## 2. 纯层（零 Vue、零 Tauri、零其它 feature）

`card-rendering/{geometry,markup,text-layout,painter,export}`：当前 0 违规，必须保持。
测试用 `// @vitest-environment node`，文本测量走注入的 `TextMeasurePort`。

## 3. 谁持有什么（Ownership）

| 对象 | 唯一持有者 | 其他人 |
| --- | --- | --- |
| 项目生命周期、文件树 | workspace/store | 只读订阅 |
| 资源环境（字体/图标/包/远程资源） | workspace 的 ResourceEnvironment | 通过端口只读使用 |
| 渲染就绪文档 `RenderReadyFace` | 上游一次产出 | Viewport / LayerView / 导出 共享，不各自重算 |
| 场景图 `CardSceneGraph` | 同上，随 RenderReadyFace 一并产出 | 只读 |
| 编辑历史 | editor-runtime/history | — |

## 4. 新代码放哪

| 你要写的是 | 放哪 | 约束 |
| --- | --- | --- |
| 数学 / 解析 / 排版 / 绘制 | `card-rendering` 纯层 | 纯函数，Node 单测 |
| 读写文件、事件监听 | `workspace/services` | 不含 UI 状态 |
| 响应式状态包装 | `*/composables` 或 `store` | 只做包装，不放算法 |
| 画布交互（拖拽/缩放/吸附的数学） | 先下沉到 `geometry/`，组件只接事件 | 组件不超过 600 行 |

## 5. 标杆文件（写新代码前先读）

- `card-rendering/geometry/matrix2d.ts`：纯函数、边界有兜底、一屏读完。
- `card-rendering/geometry/lengthMath.ts`：手写解析器，出错回退，不用 eval。
- `card-rendering/markup/cardMarkupLexer.ts`：坏输入产出诊断，不抛异常。

## 6. 反面清单

- 在纯层 import `vue` / `@tauri-apps/*` / 其它 feature。
- 往基线里的超长文件继续加代码（先拆再加）。
- 用 `as unknown as` 绕过类型，而不是修类型。
- 在 `entities` 里 import UI、feature。
