# OpenCard 资源包系统

一句话:**包就是一个文件,放进项目的文件夹里就能用。**

## 一、你要的效果

1. 包可以只属于某个项目,也可以存在这台机器上供所有项目挑用。建项目时能从机器上的包里挑几个预装进去。
2. 别人打开你的项目却发现缺包时,只提示一句,他自己去找、自己去装。
3. 将来自定义块之间会互相需要别的包 —— **这一步现在不做**。
4. 卡片里引用资源可以写死版本,也可以不写;不写就用装着的里面最新的那个。
5. 现在不做"包依赖包"。一个包自己带齐它要用的东西。
6. 项目里的包以 `.ocpack` 文件的形式**提交进 git**;解开出来的东西不放进项目。
7. 包自己说清楚自己是谁(作者、包名、版本)。**文件叫什么名字不算数**。
8. 解开出来的东西放在软件存储里当缓存,所有项目共用。
9. 要能**不解开包就知道这个包的内容特征码**。

## 二、做好之后是什么样

### 包里的东西

```
.opencard/manifest.json       ← 我是谁:作者、包名、版本
.opencard/fingerprint.txt     ← 内容特征码,一行字
.opencard/fonts/fonts.json    ← 我提供哪些字体
.opencard/icons/icons.json    ← 我提供哪些图标
还有资源文件本身
```

包里**不放依赖清单**,也**不放别人的 `.ocpack`**。用到别人的资源时,复制的是**资源文件本身**(你挑中的那些图标、字体),
引用改指到包内的新位置 —— 这就是"内化"。

对比一下,免得以后觉得不一致:

- **模板会带 `.opencard/packages/*.ocpack`** —— 模板就是一份项目,而归档跟着项目走
- **包不带** —— 包是一组资源,资源是叶子文件;"这个项目装过哪些包"是输入,不是包的内容

### 三个文件夹

| 文件夹 | 放什么 | 进 git 吗 |
| --- | --- | --- |
| 项目里的 `.opencard/packages/` | 这个项目要用的 `.ocpack` 文件 | **进** |
| 软件存储里的 `packages/` | 你自己收藏的包,建项目时挑用 | 无关 |
| 软件存储里的 `templates/` | 你自己收藏的项目模板,建项目时挑用 | 无关 |
| 软件存储里的 `cache/` | 一切可以随手删的派生数据 | 无关 |
| ├ `cache/packages/<特征码>/` | 开过的包 | 无关 |
| ├ `cache/network/` | 网络资源缓存 | 无关 |
| └ `cache/staged/` | 撤销待恢复的资产字节,启动时清空 | 无关 |

顶层的规则一句话:**`packages/` 和 `templates/` 是你有的东西,`cache/` 是可以扔的东西。**
缓存内部的规则同样一句话:**一个种类一个目录,哪个种类需要簿记就把簿记放在它自己的目录里**
(详见 [存储布局](./存储布局.md))。

包和模板**磁盘上不合并**,但用户那边本来就是一件事:新建项目时"选个模板起手"和"顺便预装几个包"是同一段流程里的两步。
这个"放一起"发生在界面上,不是磁盘上。两者也不需要任何耦合 —— 模板的 `content/` 就是一个项目文件夹,
里面本来就包含 `.opencard/packages/`,所以**模板可以自带它要用的包**。

由此一条要改的用法:**从项目导出模板时,不要把 `.opencard/packages/` 排除掉。**
老计划里是排除的(那时归档靠 `.gitignore` 挡在 git 外);现在归档要跟着项目走,模板也该带上,
否则从模板建出来的项目一开局就缺包。(排除哪些是导出时勾的,不是写死的 —— 这是用法,不是改代码。)

把网络资源缓存收进 `cache/network/`、把解开的包收进 `cache/packages/`,是为了让 `cache/` 根上只剩
"每个种类一个目录":品类和它的簿记待在一起,哪块能删一眼看得出。

- **项目里有哪些包 = 项目文件夹里有哪几个 `.ocpack`。** 不需要另外写一份清单,也不需要写 `.gitignore`。
- 把一个包装进项目:从软件存储复制一份进去,或者直接把文件拖进去。**装进去就算数**,机器上那份删了也不影响。
- **文件名就是它自己的坐标**(`作者@包名@版本.ocpack`),所以同一个包再装一次是覆盖同一个文件,
  同一个坐标换了一份内容是就地替换 —— 项目里有且只有这一份,不会多出一个 `-2` 之类的副本。
  分隔符用 `@`:它不可能出现在作者、包名或版本里,所以两个不同的坐标不会撞成同一个文件名。
- 因为文件提交进 git,别人拿到你的项目,打开就能用。

### 用的时候发生什么

- 程序打开一个包,只读里面两个小小的说明文件,就知道它是谁、内容特征码是什么 —— **不用解开**
- 打开项目时,程序扫一遍项目里的 `.ocpack`,把还没解开的那几个**排上队**,然后继续做别的事 ——
  **不等它**。整包解开到软件存储的 `cache/packages/` 里,解完自动重画一次,引用它的图标与字体这时候出现
- 所以某个包在这台机器上**第一次**被用到时,会空一拍(一次解压的时间),随后自己补齐;之后任何项目再用都是现成的
- 解开的位置就是 `cache/packages/<特征码>/` —— **一层,文件夹名就是那串 sha256**,不再套作者/包名/版本。
  所以同一个包被多少个项目用,都只解一次。名字不好看没关系:要认它是谁,读里面的说明文件就知道。
  而且说明文件本身也算进内容,所以**一串特征码只对应一个包**,不可能两个包撞进同一个文件夹。
- 这份缓存有自己的大小上限(先定 2 GiB);超了就从最久没用到的开始删,删掉也不要紧,下次用到会重新解一次。
  "最后用到"记在缓存根上一个 `.used.<特征码>` 空文件的修改时间上(命中已解开的目录时刷一下),
  占用多大在清理时现量 —— 目录名就是内容指纹,量出来的值不会变,不值得再维护一份必须和磁盘保持一致的清单

### 包里那张指纹纸条

`fingerprint.txt` 里只有一行字:64 个十六进制字符(也就是那串 sha256)。

它是把包里所有文件的真实内容按顺序算出来的。所以:

- **内容一样,这行字就一样** —— 不管谁打的包、用什么压缩、什么时候打的
- **读它不用解开包** —— 程序能直接跳到包里那个小文件,只读它一个

要注意:这行字是**包自己说的**,不是别人给它盖章。不过真正用到它的时候本来就要把包解开,那时候顺手重算一遍对一下就行,不额外花时间。

**包里没有这张纸条的,不是一个包**:不进目录,谁引用它谁在渲染时得到 `package-unavailable`。

不做"现算一个凑合着用"的退路 —— 算字节哈希要把整个文件读一遍,而目的只是给一个我们本来就不认的包取个名字,不值。而且唯一的打包器是我们自己,它一定会写这张纸条;真出现没纸条的包,那不是旧格式,是它根本不是一个包。

### 卡片里怎么引用

- `alice/icons@1.0.0#icon:d6` —— 指定 1.0.0 版
- `alice/icons#icon:d6` —— 不指定版本,用装着的里面最新的那个

两种写法的分工就一句:**要长相钉死就写版本,无所谓就不写。**

- 写版本 → 缺包提示能精确说到"需要 1.2.0",装上就一致
- 不写版本 → 项目里有这个包的任何版本都能用,所以不存在"装错版本";代价是长相会随你往项目里换包而变

**缺包不新造提示渠道**,走卡片渲染已有的问题通道:报一条 `package-unavailable`,和"图标找不到""路径不合法"是同一类东西。
表现成什么样(那一处空着,还是整张卡标红)由渲染那边已有的规则决定,包系统不掺和。

**包里那张公开列表与包内注册表不做校验。** 它们是描述:包里说"我有这个图标"而其实没有,就等卡片真的去画它的时候报一条渲染问题 ——
和 ocdocument 引用一张不存在的图片完全是同一回事。所以打开项目时不会挨个去确认包里的文件都在不在 ——
一个装了一千多个图标的包,那样做就是一千多次文件系统往返,而结论和"用到时自然发现"没有任何区别。

## 三、老的那套怎么处理

### 删掉

- **"包的来源地址"这个概念** —— 路径、相对/绝对、本地/远程之分,全删
- **从网上下载包** —— 现在没有 marketplace,包只来自"你手上有这个文件"
- **归档旁边那份 `hash.txt`** —— 它本来是"某个权威方放一份哈希让你核对"。现在归档住进项目里,旁边没有权威方;而且那份到底是谁放的、凭什么信,一直没有答案
- **项目里的包清单文件** —— 文件夹里有什么就是有什么
- **包内容校验** —— 加载项目时挨个确认包里注册表指向的文件都在。包内注册表是描述性的,缺什么由用到它的地方报渲染问题;这条校验只把打开项目的代价按包里的文件数放大了
- **包里再带一份依赖清单** —— 这一步不做依赖
- **"下载齐 → 安装 → 删除多余的"这一整套流程** —— 现在只需要"用到了就解开"
- **项目里按 `作者/包名/版本/` 分三层文件夹** —— 直接平铺就行
- **打包时那句"你依赖了本地来源的子包,不允许"的报错**
- **软件存储里的 `downloads/`** —— 它本来是"远程包下载的临时目录"。新计划不下载包了,它没有生产者

### 留着但要改

- **算内容特征码的规则留着**,但从"外面传进来核对的值"改成"写进包里那张纸条"。
  规则要动一处:算的时候把纸条自己排除在外。所以算出来的值会和以前不一样 —— 反正是新格式,旧值不用管。
- **身份解析**(把 `作者/包名@版本` 拆开的那段代码)留着,它是唯一一份实现。

### 原样留着

- 解开包时的安全检查和大小上限
- "先解到临时位置,整个解完再挪过去"的做法(避免解到一半坏掉)
- 包的公开字体与图标索引
- 软件存储里"导入 / 列出 / 删除包"

## 四、动手顺序

1. 包里的说明文件加上"我是谁";打包时把指纹纸条写进去
2. 打开项目时扫一遍项目里的 `.ocpack`,读出每个包是谁
3. 用到时按指纹解开到软件存储的缓存里
4. 卡片引用按上面的规则解析;缺包报成渲染问题
5. 把第三节说删的东西删掉
6. 补发布说明(面向用户,不写代码术语)
