# OpenCard 实现指南

按主题记录"东西放在哪、怎么接"。工程约束见 [工程规则](./工程规则.md)，UI 约束见 [UI_RULES](./UI_RULES.md)。

## 软件存储

软件存储只有一个根：`~/.opencard`。项目内的 `<项目>/.opencard` 与它同名、层级不同、内容不相干，任何一方路径都不得由另一方的常量拼出来。webview 数据（`EBWebView`）由系统与 Tauri 管理，安装目录属于发布物且只读，两者都不属于本布局，软件不得清理或写入。

顶层是闭合集合，只有八项：

| 条目 | 内容 | 没运行时删掉 |
| --- | --- | --- |
| `settings.json` | 用户偏好：外观、编辑行为、导出选项、缓存上限 | 回到默认值 |
| `app-state.json` | 长期状态：最近项目、上次创建位置、侧栏布局、各项目界面记录 | 忘记这些历史，项目文件不受影响 |
| `update-state.json` | 已读版本说明与待安装更新 | 更新提示重来一次 |
| `feedback-receipts.json` | 已提交反馈与官方回复 | 反馈记录丢失 |
| `packages/` | 用户导入的包 | 包丢失 |
| `templates/` | 用户保存的项目模板 | 模板丢失 |
| `locales/` | 用户界面语言文件 | 该语言消失，回到默认语言 |
| `cache/` | 派生与暂存数据 | 没有损失 |

```
~/.opencard/
├─ settings.json / app-state.json / update-state.json / feedback-receipts.json
├─ packages/<slug>.ocpack
├─ templates/<id>/{template.json,content/…}
├─ locales/<名字>.json
└─ cache/
   ├─ snapshots/{.used.<sha256>, <sha256>/…}   # 解开后的包
   ├─ network/{index.json, <项目名>-<路径哈希>/<uid>.<ext>}
   └─ staged/<operationId>/<序号>-<文件名>      # 撤销待恢复的字节
```

规则：

- 设置与长期状态各有模型与仓储，不互相夹带；重置设置不改长期状态，清 `cache/` 也不清它。
- 两份 JSON 用当前结构：未知字段忽略、缺失补默认、不用版本号拒绝读取、不加迁移分支。
- 外观里 `appearance.themes.dark` 与 `light` 各自保存完整主题（`colors`、`accentNeighborAngle`、`fontFamily`、`presetId`、`presets`）；颜色存实际值，不另设覆盖表；当前主题与自定义预设的 `definition` 用同一套结构。
- 目录名必须能从输入直接算出：包快照用内容指纹 `<sha256>`，网络缓存用 `keySlug(项目目录名)-<规范化项目路径哈希前 8 位>`。不得引入"身份 → 目录名"的持久映射表，它只会随改名漂移。
- 一个名字只表达一个意思。语言文件名就是身份（`<名字>.json`），界面显示名是去掉扩展名的文件名；内置语言 id 不带扩展名，所以用户同名文件顶不掉内置语言。
- 语言文件声明 `base`（`zh-CN`、`en-US` 或 `keys`）与嵌套 `messages`；`keys` 基底让缺省文案显示完整 key。
- 簿记与被记录对象放在一起，不平级并列；缓存条目目录内不写簿记（包快照目录只含包自己的文件）。
- 清理排序依据越少越好：包快照只记"最后一次用到"（缓存根的 `.used.<指纹>` 修改时间），体积现量；网络缓存另需字节数与刷新时刻，所以有 `index.json`。簿记读不出来只影响清理顺序，不得阻止缓存使用。
- 一个文档一个文件：文件内的键属于持久化协议，改键必须按 [命名规范](./命名规范.md) 单独规划读写两端。

`cache/` 规则：

- 运行时 `cache/staged` 里的字节正是撤销要恢复的内容，删它会破坏撤销；软件没运行时删整个 `cache/` 没有损失。
- 启动维护一次：清空 `staged`，对 `snapshots` 与 `network` 分别按各自字节上限 LRU 淘汰（默认 2 GiB / 1 GiB，设置页"缓存"卡片可改）。会话进行中不淘汰，超出部分留到下次启动。
- 强杀留下的 `staged` 字节随下次启动清掉（撤销栈本来就不跨进程）；解压到一半的目录以 `.` 开头，启动时直接删。
- 历史位置不再读写，需要回收空间时手工删除：`history/`、`cache/unpacked*`、`cache/packages/`、`cache/<uuid>/`、`%LOCALAPPDATA%\per.yiguwang.opencard\templates\`、旧的 settings 位置、旧 identifier 的 `EBWebView`。

路径归属：`opencard-app/src/shared/storage/appStoragePaths.ts` 是软件存储路径的唯一出口，根名与每个顶层条目名只在那里出现。Rust 侧不得自己拼 `.opencard`：命令接受前端传入的绝对路径。新增顶层条目必须同时改路径定义与本文件。

## 资源包

包就是一个文件，放进项目文件夹就能用。

- **身份来自包内清单**（作者、包名、版本），文件名不算数。包内结构：`.opencard/manifest.json`（身份）、`fingerprint.txt`（内容 sha256，一行 64 个十六进制字符）、fonts/icons/blocks 注册表与资源文件本身。
- **包不带依赖清单**，也不嵌别人的 `.ocpack`。用到别的包的资源时复制资源文件本身并把引用改指到包内新位置（内化）。项目与包按同一套 `block:key` 与路径引用规则解析。
- **没有 `fingerprint.txt` 的不算包**：不进目录，引用它报 `package-unavailable`。不做"现算一个凑合"的退路 —— 打包器是我们自己的，一定会写。
- **三处放置**：项目内 `.opencard/packages/*.ocpack`（进 git，装进去就算数，同名覆盖，文件名原样保留）、软件存储 `packages/`（收藏）、安装目录 `packages/`（内置，只读）。
- **模板会带上** `.opencard/packages/`：从项目导出模板时不要排除它，否则从模板建出的项目开局缺包。
- **内置包**：把 `.ocpack` 放进 `opencard-app/src-tauri/resources/packages/`，重启（开发）或重新打包即可，不需要索引文件；同坐标多版本可并存，不写版本的引用取最高版。开发环境资源目录为空只表现为"没有内置包"。
- **使用时**：打开项目扫一遍项目里的 `.ocpack`，未解开的排队后台解到 `cache/snapshots/<指纹>/`（一层，按指纹共享，所有项目共用），首次会空一拍，解完自动重画。归档上限 64 MiB / 10000 条目 / 解开后 256 MiB。
- **引用**：`alice/icons@1.0.0#icon:d6` 钉死长相，`alice/icons#icon:d6` 用装着的最新版。缺包不新造提示渠道，走渲染问题 `package-unavailable`。
- **解开时**先解到临时位置，整个解完再挪过去（避免半成品被当成有效快照），并走统一的归档安全检查与大小上限。
- **不校验包内注册表**：公开列表是描述，缺文件由用到时自然报渲染问题；打开项目时不逐个确认包内文件，以免按包内文件数放大启动代价。

## 教程

业务主动通知：业务决定开始与完成时机，store 管进度，根部 `OcTutorial` 自动显示。只运行一组，退出后从头开始。

1. **标记目标**：`<aside data-oc-tutorial="workbench.files">`。同一目标 key 在当前可见界面中唯一；共享侧栏列表用 `ShellList.tutorialKey`。
2. **加定义与文案**：在 `opencard-app/src/features/tutorials/tutorials.ts` 的 record 中加一项，title 与说明是 i18n key，中英文都要补齐。
   - 步骤 `manual: true` 显示"下一步"，省略则等待业务通知。
   - `targets` 可含多个区域（同时高亮、一张说明卡）；无定位的欢迎步骤用 `targets: []` + `message: { title, desc }`，`nextLabel`/`exitLabel` 可改按钮文案。
   - 操作型教程只允许点击当前高亮区域、它们打开的浮层与教程按钮，其余区域由遮罩接收命中。单个目标 `interactive: false` 保持高亮但禁止交互；`blockInteraction` 可覆盖整组（纯演示教程设 `true`）。
   - 侧栏、底部面板按当前目标 `shell.sidebar`、`shell.bottom-panel` 临时展开，结束该步骤后恢复。
3. **通知**：`tutorial.start('openFile')`；异步操作先记 `const run = tutorial.session.value?.run`，完成后 `tutorial.completeStep('openFile', 'open', run)`，避免退出重开后的旧结果推进新教程；`tutorial.exit()` 不回滚业务操作。

看过的教程记在 `settings.json` 的 `tutorials.seen`，启动时自动登记，可在设置里以标签管理：清理缓存不清除，重置设置会清除；移除标签后可再次触发。

## 交互性能模式

约束见 [工程规则·交互性能](./工程规则.md#交互性能)，这里是可直接沿用的实现。

- **连续输入只改视口**：平移、缩放、滚动位置属于视图状态，不应触发文档解析、资源重建或项目扫描。用 `src/utils/taskScheduler.ts` 的 `frame` 采样：同帧 `schedule` 覆盖旧位置，`flush` 保留松手前最后一次输入，`cancel` 丢弃已销毁视图的输入。它适合位置采样，不能用于丢弃增量、文字输入或文件操作。缩放动画仍由自己的帧循环推进。
- **测量与投影分开**：内容或布局变化后集中测量；平移缩放只用已有坐标算画面位置，不要每次位置变化都等 DOM 更新再读边界。`CardViewport.vue` 把选框存成画布坐标再换算视口坐标；修改文档、改选中、容器尺寸变化才重新测量。
- **列表更新止于可见范围**：结构索引负责父子关系、视觉顺序与键盘导航；滚动只读可见范围与少量预渲染行，范围没变就复用范围对象与行数组。共享 `OcTree` 负责窗口、`OcTreeRow` 负责行内订阅：行身份稳定，滚动进一行不应让其余行插槽全部重跑。调用方复用它的虚拟化，不自己写窗口算法；菜单子项在打开时才解析。
- **后台结果有预算也有归属**：目录排序、差异、大资源整理交给共享项目索引 Worker，主线程用 `taskScheduler.runBatched` 或 `forEach` 应用；每批 256 项、约 4ms，单步里的巨型 `sort`/`JSON.parse` 仍会阻塞。后台任务必须持有所属项目与取消信号，先生成完整新快照、确认请求仍有效再发布，失败保留旧快照。
- **回归检查**：同范围滚动不重复呈现；跨范围只新增进入视口的行；一帧多次输入只发布一次；平移不重新测量；最后一次位置必须提交；取消、销毁、切项目后不发布旧结果。实际耗时分别记录开发版与生产版的逐帧间隔 —— 平均帧率和单元测试都不能替代实际帧耗时。
- **入口**：`OcTree.spec.ts`、`CardViewport.spec.ts`、`useCdeViewportController.spec.ts` 与项目资源、目录相关测试。可复现页面 `opencard-app/performance/interaction.html?files=100000`（生产构建用 `scripts/performance-vite-config.ts`）。
