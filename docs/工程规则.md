# OpenCard 工程规则

只记录已明确确认、必须持续遵守的规则。未经确认的建议与阶段计划不写入。

## 命名

- 源码、测试、脚本、资源遵循 [命名规范](./命名规范.md)。
- 普通重命名不得改持久化字段、类型判别值、Tauri command、i18n key、样式 token 等协议名称。
- 用户可见名称转机器 key 只用 `shared/model/keySlug.ts`，不新增 feature 局部 slug；可用性检查不区分大小写。

## 应用文案

- 文案只接受 `[b] [i] [code] [key] [br] [icon:<token>]`，且只能经 `OcInlineMarkup` 渲染；不渲染任意 HTML，不扩展成通用 BBCode。

## 持久化数据

- `CardDocument`/`CardBlock`/Location/`CardInstanceRecord` 中普通属性值一律为字符串，不得为 `null`；对象与数组保持领域结构。
- 用户输入的错误值永久保留原字符串；渲染投影用字段默认值参与渲染，但不得改写原值。
- 文档持久化只做 JSON 解析与序列化：保存与读取不投影、不过滤、不补默认值、不迁移、不重写。
- 打开项目或读取、只读编辑管理文件时不得创建 `.opencard`；缺失文件用内存初值，首次保存时只创建对应文件与父目录。

## 实例覆盖

- `instance.data[blockId][fieldKey]` 存在字符串值 = 覆盖，不存在 = 继承蓝图；只有这两种状态，不得存 `null`。
- 创建 = 新增 key，更新 = 改值，Reset = 删 key。

## 渲染链路

- 状态顺序：磁盘 JSON 文本 → 原始编辑数据 → 蓝图待渲染 → 实例合并 → binding 展开（值仍为字符串）→ 属性转换 → 安全渲染数据 `Render*Block`。
- 属性字符串无法转换或缺字段时，用字段默认值参与渲染并记录错误。
- `Render*Block` 已完成空值补齐、类型转换、合法性检查与默认值回退；renderer 只把它转成 CSS/SVG/二维码/DOM，不得重复做这些事。
- 渲染诊断记录错误字段的位置与原因。
- `custom-block` 只持久化 source 与用户字段值，展开后的 children 不写回文档；`.ocblock` 存容器模板与 publicFields。
- 自定义块在 override 后、引用解析前由共享 materializer 投影为普通容器树；`CustomBlockRenderer` 只负责状态边界。
- 允许递归引用，不检测循环；单次运行最多 32 层、10000 节点，超限分支显示 limited 占位。
- 模板后代 ID 是本次运行的确定性 ID，不得持久化或进入版本控制；实例 ID 保留用于 override、选中与诊断。

## PropertyEditor

- 属性值在领域与持久化中都为 string；array/object 保持结构；number、boolean、null 不是合法持久化值。
- `fieldType` 只描述编辑能力与逻辑类型，不改变 string 持久化形式；只有 RenderParser 能转成渲染类型。
- `PropertyEditor` 只接收调用方整理好的 records、字段定义与分类定义，不接收 Card/Block/Store/文件系统对象；只展示并 emit 意图，不直接改领域数据。
- 基础 Block 用内置 scheme 与 additional field definition 拼装后传入；additional field 的创建（弹窗、检查、字段创建、records 更新）由上级模块控制。
- definition 不保存 `defaultValue`；上级 command 按 `fieldType` 用统一初值策略一次性创建 Stored 值。
- 字段可删除性由 `deletable` 显式声明；删除需同一行按钮连续点击两次确认。
- 自定义块 source 是内置字段，其 publicFields 与记录合并后交给 PropertyEditor；PropertyEditor 不读 `.ocblock` 或文件系统。

## Additional Field

- 值存 `block[fieldKey]`，与原生字段并列，不另设 value 容器；definition 只存 `block.additionalFieldDefinition[fieldKey]`。
- 原生字段与 additional 定义合并成完整字段定义再传 PropertyEditor。
- 实例覆盖存 `instance.data[blockId][fieldKey]`；删除字段清理所有实例的对应 override，但不改写其他字段的 binding 表达式。

## 通用 UI

- 调用方把领域数据整理成 UI 规定的结构，不把整个 model 交给通用 UI 判断。
- 通用 UI 通过 emit 返回带稳定 key 的意图，不直接改传入数据；Action definition 只描述标题、图标与层级，由上级解释执行。
- `OcTree` 不内置重命名：`renamable` 只决定节点能否进入重命名，`rename.request`/Action 请上级调用 `beginRename(key)`；组件只维护瞬时 draft，提交经 `rename.commit` 由上级验证并落盘。
- `OcTree` 外部拖放：只有声明接收的实例注册投放区，未声明的让给窗口级处理；组件只上报落点与平台负载，不解释负载。
- 窗口级拖放只实现一份命中与坐标换算；未被区域消费的投放交给未处理回调。

## 软件壳层与空间页

- 术语：`Shell` 固定框架、`Page` 空间页、`Workbench` 工作台业务、`workspace` 只指项目/资源环境/持久化设置。
- 壳层持有标题栏、导航、侧栏框架、内容页头、下方面板及布局状态；页面选择只有软件级导航一份真相；页头 `header.value` 为 null 时不保留占位。
- 空间页由 `initializeAppPages()` 统一初始化，重复初始化复用实例，`useAppPages()` 只取实例。页面通过 `SpacePage` 提供侧栏、页头、问题、菜单与内容组件；切页只切展示模型，内容按需挂载、运行状态不销毁。
- 壳层只显示页面模型并调用回调，不解释编辑器、模板或设置业务。页头、侧栏组/列表、菜单贡献各自提供 `actions + onAction(key)`，壳层不设中央解码表。展开菜单保留当时的贡献者；保存、撤销、重做只作用于当前工作台。
- 编辑器用 `headerActions` 与 `onHeaderAction` 提供页头动作，动作与忙碌检查归编辑器；回调捕获会话与贡献者身份，失效后停止。
- 图片导出复用工作台唯一渲染器；文件选择前捕获来源、名称、正反面与倍率。
- 新建项目与模板导出表单归页面运行实例；内容卸载不清空草稿，新流程明确重置，异步结果不得写回其他项目。
- 更新、反馈、全局弹窗属软件服务；应用根初始化，卸载时释放监听、计时器与共享引用。
- 删除文件与放弃版本修改先收集全部受影响会话再统一确认；取消或保存失败不得开始改磁盘。项目资源刷新统一走项目资源入口。
- 工作台私有地组织会话、文件树、版本控制与导出；跨页打开与项目切换走软件级项目操作入口。切换项目、删除已编辑文件、关闭应用必须经过未保存确认。

## 编辑器会话

- 工作台拥有唯一会话管理器：只管理打开、集合、选择、路径重映射与释放，不提供全局 store。每个资源从打开到关闭保持同一对象实例；另存为、重命名、切空间不替换实例。
- 会话以只读 `state` 提供身份、内容、保存基线、比较与视图状态；内容更新、刷新、保存、另存为、撤销、重做都调用实例方法。公共协议在 editor-runtime，不在 Host 或注册表定义。
- 编辑器接收自己的会话，声明 `presentation`、`headerActions`、`onHeaderAction`、`canSave`、问题与可选刷新/定位；所有保存入口走同一个 `session.save()`，保存先刷新再校验，`skipped`、取消、失败都不能通过未保存确认。
- 内容读取方式、历史类型、即时自动保存策略登记在编辑器定义；视图状态按编辑器 ID 保存，字段语义归编辑器。
- Host 为捕获的会话与挂载身份创建绑定，展示、问题、动作、刷新共用；解绑后旧回调失效，最后一个绑定解除即释放模型与历史。
- 同一会话串行保存，不同会话独立；每次写入捕获路径与内容，完成后只更新原实例，写入期间的新修改保持未保存。同路径并发打开复用读取，迟到结果不得抢走后来的选择。
- 定时自动保存只有一个触发器；即时自动保存任务归会话，切页继续、关闭取消。破坏性操作先刷新再统一确认。
- 会话持有"这份工作是什么"，编辑器只渲染并按声明上报意图；编辑器不直接改壳层状态，由 Host 把 `presentation` 写回会话。
- 页头与"打开的编辑器"列表读同一份会话呈现，任何表面都不得直读编辑器实例或自行拼装标题/图标。身份变化时丢弃旧呈现：仍挂载则按新身份重新声明，否则退回身份名。
- 只有活动实例才有的信息（随选区/忙碌变化的头部动作）仍由编辑器声明并由工作台直读；只有后台会话也要显示的信息才写回会话。

## 资源环境

- `createResourceEnvironment(folder, { watch })` 是稳定运行实例，持有资源定义、解析缓存、字体与任务；项目模块只投影其只读状态，不维护第二份可写数据。
- 当前项目持有启用监听的环境，每个环境独立原生 watcher；文件操作与监听通知走同一按路径批次刷新入口，目录变化同时失效后代。异步结果只向原实例发布。
- 会话不持有环境：工作台 Host 显式传入，外部卡片用当前项目环境，无项目传 `null`，不得从文档目录创建隐式环境。
- 比较运行状态按 session 身份由项目持有，切文件/空间保留，退出比较、关闭会话或项目时释放；历史侧还原完整项目并创建不监听的环境。比较先释放环境再删自己创建的临时目录。
- 图标尺寸按目录条目归环境缓存；字体按实例与作用域独立释放；包解压目录按内容指纹共享，包引用统一按坐标规则解析。网络磁盘缓存可共享，运行请求与发布归环境，等待缓存期间不得绕过缓存直连。
- 自定义块默认字段用模板来源作用域，用户覆盖的公共资源字段用调用者作用域；显式宿主或包坐标引用按声明解析。文档保存稳定引用，不保存环境实例的字体名。
- 关闭项目、切换、安装更新先完成未保存确认，再取消并等待旧项目的导出准备、渲染与写入，最后释放环境；缓存清理只在项目关闭且任务释放后执行。

## Card Designer

- 蓝图与以蓝图为模板的实例模式是必要能力；实例属性使用 override/reset 模式。

## 本地化

- 任何 i18n 改动必须在同一次改动里更新全部受支持语言，不得只改一种。
- 用户语言文件（`~/.opencard/locales/<名字>.json`）只能覆盖其声明基底里已存在的条目；未写、基底没有、结构不符的保留基底值，不得新增 key。
- 支持 `"base": "keys"`：沿用内置英文 key 结构，未填或无效条目显示完整 key。
- 语言 id 就是文件名（含 `.json`），内置语言 id 不带扩展名；界面显示名是去掉扩展名的文件名。
- 选中的语言文件读不到时退回系统默认语言并提示，不改写设置；文件放回后重读即恢复。

## 读取容错

- 读取方必须结构容忍：缺字段取当前 schema 默认值；多余、已移除、未知、格式错误的字段忽略或告警，不得使文档或包不可读。
- 不为旧结构加黑名单或特殊拒绝路径；能形成可用当前投影就继续。
- 硬失败只留给完全无法形成当前投影的数据（JSON/归档损坏、路径不安全、超出资源上限）。

## 项目字体

- 每个项目字体保存名称、项目内唯一 Key、最多六个项目相对路径槽位（Light/Normal/Bold × upright/italic），至少一个。
- 粗细是语义枚举 `light|normal|bold` → `300|400|700`；缺失槽位保持缺失，由浏览器匹配或合成，回退提示不得持久化。
- Key 不区分大小写唯一；省略时由名称推导为可用序号。
- 用户可见引用只有 `font:<key>`；字体字段接受按回退顺序分号分隔的列表，所有渲染方走共享字体模型转换。
- 字体元数据对槽位的归类是瞬时状态；TTC 集合索引只用于导入，不进注册表。不为已移除的 face 描述符或数字粗细加兼容解析。

## 项目图标集

- 只有一个模型：不区分大小写唯一的名称 + Key + 有序图标列表，每个图标恰好一个项目相对路径文件；没有精灵表、裁切范围、集级 `source`。
- 图标保存 `source`、`tint` 与可选 `pixelated`，不支持旋转；`source` 只支持 `.svg/.png/.jpg/.jpeg/.webp`。
- `tint`：`context` 用文件 alpha 作遮罩绘制在上下文 `currentColor` 上，`original` 保留原色；导入时探测默认值，可逐图标覆盖，不得为整集猜一个。
- `pixelated` 只属像素画且逐图标设置，不推测、不整集套用。
- 绘制走共享 `.oc-project-icon` 契约，renderer 由 `--oc-project-icon-renderer` 选择；使用者问 `shared/ui/visual/projectIconStyle.ts`，不自己判断取值。
- 一个文件夹只属一个图标集：图标放 `<图标目录>/<集合Key>/`，文件名严格等于图标 Key 加原扩展名；导入文件或文件夹，分享用 `.ocpack`，不得平铺写入图标目录根。
- 写入前解析文件夹：更早的图标集不得吸收新文件，冲突时给文件夹名加序号（`<集合Key>-2`）而不是改内部文件名；存在但空的文件夹原样复用。
- 追加图标写入该集**现有**文件所在文件夹（取自已有图标的 `source`），不按 Key 另开文件夹（集合可能已改名或带序号）。
- 追加时新图标名必须避开已有 Key；排序、边界移动与批量命令作用于当前选中集。不得重新引入精灵表或把独立图标合并成图集。
- 导入时每个文件只读一次（探测 tint 与位图尺寸），并用 `shared/async/mapWithConcurrency.ts` 并发探测。

## 应用图标

- macOS 应用图标唯一源文件是 `opencard-app/src-tauri/icons/OpenCard.icon`，由 `bundle.icon` 编成 `Assets.car`；不得手改 `Assets/` 里的结构。
- `icon.icns` 是 macOS 26 以下的回退，必须由同一份 `.icon` 生成：`ictool` 渲染 1024 图、居中缩到 824 留安全边距，再走 `tauri icon`。
- 编 `Assets.car` 需要 Xcode 26+ 的 `actool` 且 `xcode-select -p` 指向 Xcode；否则打包器记一条错误并回退 `icon.icns`，不中断构建。
- `.icon` 带 quarantine 时 `actool` 报 `Bad file descriptor` 并中断，取回或解压后先 `xattr -cr`。
- 开发模式只在 macOS 用 `.icns` 设 Dock 图标；`.icon` 的分层效果只出现在打包后的 `.app` 里。

## 安装磁盘映像

- DMG 背景、窗口尺寸与图标位置只写在 `src-tauri/tauri.macos.conf.json` 的 `bundle.macOS.dmg`，背景图是 `src-tauri/dmg/background.png`。
- macOS 26+ 上 Tauri 自带的美化脚本失效，出包后必须跑 `npm run dmg:restyle`（`scripts/restyle-dmg.mjs`）用绝对路径重设背景与布局。
- 发版在 tauri-action 之后用同一脚本重刷镜像并覆盖已上传产物；脚本失败则发版失败，不得静默发布无背景镜像。

## 交互性能

- 滚动、拖拽、缩放、面板动画以 60fps、每帧 16.7ms 为目标，单帧工作量不得随无关项目文件数量增长。
- 连续位置输入走共享 `taskScheduler.frame`，每帧只处理最新位置；提交前 `flush`，销毁时 `cancel`，不丢最后一次输入。实现模式见 [实现指南](./实现指南.md#交互性能模式)。
- 交互状态与文档、目录、资源投影分开；平移缩放只投影视口坐标，内容或布局变化才重新测量。
- 虚拟列表只在可见范围或对应数据变化时更新行呈现；选择不得重建结构，滚动不得遍历全部节点或预建菜单。
- 后台整理复用共享 Worker 与 `taskScheduler.runBatched`；主线程每批最多 256 项、约 4ms 让出，持续交互期间收紧到约 1ms，单步工作本身必须有界。
- 目录与资源更新按受影响路径失效；发布前验证所属项目与请求代次，旧结果不得覆盖当前。
- 性能回归同时看工作量与逐帧耗时；测试保留真实组件与索引链路，不得用平均帧率或绕过真实链路的 mock 宣称通过。

## 兼容性

- 新实现不为旧文件格式保留向后兼容逻辑。
