# OpenCard 工程规则

本文件只记录人类开发者已经明确确认且必须持续遵守的 OpenCard 工程规则。未经人类开发者明确确认的建议、推论和阶段计划不得写入本文件。

## 命名

- 仓库源码、测试、脚本和资源遵循 [OpenCard 命名规范](./命名规范.md)。
- 普通代码重命名不得修改持久化字段、类型判别值、Tauri command、i18n key、样式 token 或其他协议名称。
- 用户可见名称转换为机器 Key 一律通过 `opencard-app/src/shared/model/keySlug.ts`；不得新增 feature 局部的 slug 或冲突消解逻辑，可用性检查不区分大小写。

## 应用文案

- 应用文案只接受安全行内子集 `[b]`、`[i]`、`[code]`、`[key]`、`[br]`、`[icon:<token>]`，并且只能通过 `OcInlineMarkup` 渲染。
- 不得渲染任意 HTML，也不得把该子集扩展成通用 BBCode 解析器。
- 双括号 `[[icon:series/icon]]` 形式只用于持久化的项目图标引用，不进入应用文案。

## 持久化数据

- 在 `CardDocument`、`CardBlock`、Location 和 `CardInstanceRecord` 的持久化结构中，普通属性值全部以字符串保存。
- 在 `CardDocument`、`CardBlock`、Location 和 `CardInstanceRecord` 的持久化结构中，普通属性值不得保存为 `null`。
- 在 `CardDocument`、`CardBlock`、Location 和 `CardInstanceRecord` 的持久化结构中，对象和数组保持原有领域结构。
- 在持久化结构中，用户输入的错误属性值永久保留为原始字符串。
- 在渲染投影中，无法转换为合法渲染值的原始字符串使用字段默认值参与渲染。
- 在渲染投影中，使用字段默认值不得改写持久化结构中的错误原值。
- 文档持久化只负责 JSON 解析和 JSON 序列化；保存和读取不得按 scheme 投影、过滤字段、补默认值、迁移格式或重写 document 数据。

## 实例覆盖

- 在 `instance.data[blockId]` 中，存在值为字符串的对应 `fieldKey` 表示实例覆盖蓝图字段值。
- 在 `instance.data[blockId]` 中，不存在对应 `fieldKey` 表示实例继承蓝图字段值。
- 在实例 override 数据中，字段状态只有不存在对应 key 和存在字符串值的对应 key 两种状态。
- 在实例 override 数据中，override 值不得保存为 `null`。
- 在实例属性写入流程中，创建覆盖通过新增对应 override key 完成。
- 在实例属性写入流程中，更新覆盖通过更新对应 override key 完成。
- 在实例属性 Reset 流程中，重置覆盖通过删除对应 override key 完成。

## 渲染链路

- 在磁盘文件状态时，卡牌数据是 JSON 文本。
- 在原始编辑数据状态时，卡牌数据是由 JSON 文本解析得到的持久化结构。
- 在蓝图待渲染状态时，待渲染数据等于蓝图数据。
- 在实例待渲染状态时，待渲染数据等于蓝图数据与选中实例 override 的合并结果。
- 在 binding 待展开状态时，属性字符串可以包含 binding 表达式。
- 在 binding 已展开状态时，属性值仍然是字符串。
- 在属性转换状态时，渲染投影按照字段定义把属性字符串转换为合法渲染值。
- 在属性字符串无法转换为合法渲染值的状态时，渲染投影使用字段默认值并记录错误。
- 在持久化数据缺少内置 scheme 已定义字段的状态时，普通 Block 渲染投影使用字段默认值。
- 在安全渲染数据状态时，渲染解析直接生成各个 Vue 渲染组件所需的完整 `Render*Block` 数据。
- 在安全渲染数据状态时，`Render*Block` 中的属性值已经完成空值补齐、类型转换、合法性检查和默认值回退。
- 在 Vue 渲染组件中，普通 Block renderer 不得再次执行空值补齐、类型转换、合法性检查或默认值回退。
- 在 Vue 渲染组件中，普通 Block renderer 只将 `Render*Block` 数据转换为 CSS、二维码、SVG 和 DOM。
- 在渲染诊断状态时，诊断数据记录错误字段的位置和错误原因。
- `custom-block` 只持久化 source 与用户字段值；`.ocblock` 负责保存容器模板和 publicFields，不把展开后的 children 写回文档。
- 自定义块在实例 override 后、引用解析前由共享 materializer 投影成普通容器树；CustomBlockRenderer 只负责状态边界，不重复字段转换或创建布局盒子。
- 自定义块允许递归引用，不做循环错误检测；单次运行最多展开 32 层、10000 个节点，超限分支显示 limited 占位状态。
- 自定义块实例 ID 保留用于 override、选中和诊断；模板后代 ID 是本次运行时确定性 ID，不得持久化或进入版本控制。

## PropertyEditor

- 在 `.ocdocument` 持久化状态和 `CardDocument` 领域状态中，所有 scalar 属性值均为 string。
- 在 `.ocdocument` 持久化状态和 `CardDocument` 领域状态中，array 与 object 保持结构，number、boolean 和 null 不属于合法持久化值。
- 在字段定义中，`fieldType` 只描述编辑能力和逻辑类型，不改变字段值的 string 持久化形式。
- 在 binding 展开状态中，所有 scalar 属性值仍为 string，只有 RenderParser 可以将其转换成渲染所需类型。

- 在 `PropertyEditor.vue` 的输入协议中，PropertyEditor 只接收调用方整理完成的 records、字段定义和分类定义。
- 在 `PropertyEditor.vue` 的输入协议中，PropertyEditor 不接收完整的 Card、Block、Store 或文件系统对象。
- 在 CardEditor 属性编排模块中，基础 Block 使用内置 scheme，再与 additional field definition 拼装后传入 PropertyEditor。
- 在 `PropertyEditor.vue` 中，PropertyEditor 根据字段定义选择对应的字段编辑器。
- 在 `PropertyEditor.vue` 中，PropertyEditor 只展示 records 并 emit 用户编辑意图。
- 在 `PropertyEditor.vue` 中，PropertyEditor 不直接修改领域数据。
- 在 additional field 创建流程中，创建弹窗、可用字段检查、字段创建和 records 更新均由 CardEditor 上级模块控制。
- 在 additional field 创建流程中，definition 不保存 `defaultValue`；上级 command 按 `fieldType` 使用统一初值策略一次性创建 Stored 值。
- 在 `PropertyEditor.vue` 中，字段的可删除能力由字段定义中的 `deletable` 显式声明。
- 自定义块的 source 是内置字段，source 解析出的 publicFields 与记录合并后才交给 PropertyEditor；PropertyEditor 不读取 `.ocblock` 或文件系统。
- 在 `PropertyEditor.vue` 中，删除字段使用同一行删除按钮连续点击两次确认。

## Additional Field

- 在 `CardBlock` 持久化结构中，additional field 的实际值存储在 `block[fieldKey]`，并与原生字段值并列。
- 在 `CardBlock` 持久化结构中，additional field 不使用独立的 value 容器。
- 在 `block.additionalFieldDefinition[fieldKey]` 中，additional field definition 只用于描述额外添加的字段。
- 在 CardEditor 属性编排模块中，原生字段定义与 additional field definition 合并为 PropertyEditor 的完整字段定义。
- 在实例 additional field 覆盖流程中，覆盖值存储在 `instance.data[blockId][fieldKey]`。
- 在 additional field 删除流程中，删除操作清理所有实例中的对应 override。
- 在 additional field 删除流程中，删除操作不自动改写其他字段中的 binding 表达式。

## 通用 UI

- 在通用 UI 的输入协议中，调用方负责将领域数据整理为该 UI 规定的数据结构。
- 在通用 UI 的输入协议中，调用方不得将整个领域 model 交给通用 UI 自行判断。
- 在通用 UI 的输出协议中，通用 UI 通过 emit 返回包含稳定 key 的用户意图。
- 在通用 UI 组件中，组件不得直接修改调用方传入的领域数据。
- 在 Action 协议中，Action definition 与领域数据保持分离。
- 在 Action 协议中，Action definition 描述 Action 的标题、图标和层级关系。
- 在 Action 执行流程中，调用通用 UI 的上级模块负责解释并执行 Action 意图。
- 在 `OcTree` 的输入协议中，重命名按钮由上级模块通过普通 Action definition 和节点 Action key 显式定义。
- 在 `OcTree` 的节点展示中，`OcTree` 不得自行生成内置重命名按钮。
- 在 `OcTree` 的 Action 触发流程中，重命名 Action 与其他 Action 一样通过 `action.invoke` 返回上级模块。
- 在 `OcTree` 的 Action 触发流程中，`OcTree` 不得根据 Action key 或 Action definition 推断并执行重命名行为。
- 在 `OcTree` 的键盘交互中，F2 只通过 `rename.request` 请求上级模块开始重命名。
- 在 `OcTree` 的重命名编排流程中，上级模块接收到重命名 Action 或 `rename.request` 后调用对应 `OcTree.beginRename(key)`。
- 在 `OcTree.beginRename(key)` 的执行流程中，`renamable` 只用于确认对应节点是否允许进入重命名状态。
- 在 `OcTree` 的重命名状态中，`OcTree` 只维护瞬时输入 draft，不得修改领域数据。
- 在 `OcTree` 的重命名提交流程中，`OcTree` 通过 `rename.commit` 返回节点 key 和新名称，上级模块负责验证并修改领域数据。
- 在 `OcTree` 的外部投放协议中，只有声明接收外部拖放的 `OcTree` 实例才注册投放区域，未声明的实例必须把投放让给窗口级处理。
- 在 `OcTree` 的外部投放协议中，`OcTree` 只上报落点节点、落点位置与平台负载，不得解释或改写负载内容；是否接受、复制、移动或拒绝由上级模块决定。
- 在窗口级拖放机制中，命中判定与坐标换算只实现一次；投放区域由调用方显式注册，未被任何区域消费的投放交给未处理回调。

## 编辑器会话

- 在会话与编辑器的分工中，会话持有"这份工作是什么"（身份、内容、状态、对外呈现），编辑器只负责渲染它、声明自己对外长什么样，并上报意图。
- 在呈现的写入路径中，编辑器不得直接改壳层状态；由 Editor Host 把编辑器的 `presentation` 写回会话，编辑器仍通过同一个声明入口表达要求。
- 在呈现的读取路径中，页面顶端与"打开的编辑器"列表读同一份会话呈现；任何表面都不得直读编辑器实例，也不得自行拼装标题或图标。
- 在会话身份变化时（另存为、重命名），会话丢弃编辑器先前的呈现；编辑器仍挂载时按新身份重新声明，未挂载时退回到身份名。
- 在编辑器动作的归属中，只有活动实例才存在的信息（随选区、忙碌态变化的头部动作）仍由编辑器声明、壳层直接读取；只有"后台会话也要显示"的信息才写回会话。

## Card Designer

- 在 Card Designer 领域模型中，蓝图与以蓝图为模板的实例模式属于必要能力。
- 在 Card Designer 实例编辑流程中，实例属性使用 override/reset 模式。

## 本地化

- 任何 i18n 文案改动必须在同一次改动中更新全部受支持语言；不得只在单一语言中新增、删除或修改 key。
- 用户语言文件（`~/.opencard/locales/<名字>.json`）只能覆盖它所声明的内置基底语言里已存在的字符串条目；未写、基底没有、结构与基底不符的条目一律保留基底的值，用户文件不得新增 key。
- 语言 id 就是语言文件名（含 `.json`），内置语言 id 不带扩展名，两者不共用命名空间；界面里显示的名字是去掉扩展名的文件名。
- 设置里选中的语言文件读不到时，运行时退回系统默认语言并提示，不得改写设置里的选择；文件放回后再次读取即恢复。

## 读取容错

- 当前模型的读取方必须结构容忍：缺失字段取当前 schema 默认值；多余、已移除、未知或格式错误的字段被忽略或作为警告上报，且不得使整个文档或包不可读。
- 不得为旧结构增加黑名单字段或特殊拒绝路径；旧数据没有特殊地位，凡能形成可用当前投影即继续。
- 硬读取失败只保留给完全无法形成可用当前投影的数据，例如 JSON 损坏、归档损坏、归档路径不安全或触发的资源上限；语义不完整应优先取默认值、省略、标记不可用或上报诊断。

## 项目字体

- 每个项目字体保存名称、项目内唯一 Key，以及最多六个项目相对路径文件槽位：Light、Normal、Bold 各含 upright 与 italic；至少存在一个槽位。
- 文档字体粗细是语义枚举 `light | normal | bold`，渲染为 `300 | 400 | 700`；缺失的项目字体槽位保持缺失，由浏览器匹配或合成，UI 回退提示不得持久化回退路径。
- 项目字体 Key 不区分大小写地唯一；省略的 Key 由字体名称推导并解析为可用序号。
- 用户可见的项目字体引用只使用 `font:<font-key>`；字体字段接受按回退顺序以分号分隔的引用列表，所有渲染方必须通过共享项目字体模型转换。
- 字体元数据可以把导入文件归类到槽位，但它只是瞬时状态；TTC 集合索引仅用于导入，不得进入注册表。
- 不得为已移除的 face 描述符或数字文档粗细增加兼容解析。

## 项目图标集

- 项目图标集只有一个模型：不区分大小写唯一的名称、一个 Key，以及有序图标列表，其中每个图标恰好拥有一个项目相对路径文件；不存在精灵表、裁切范围和集级 `source`。
- 每个图标保存自己的 `source`、`tint`，以及可选的 `pixelated` 和 `rotation`；`source` 只支持 `.svg`、`.png`、`.jpg`、`.jpeg`、`.webp`。
- `tint` 决定绘制方式：`theme` 以文件 alpha 作为遮罩绘制在 `currentColor` 上，`original` 保留文件自身颜色；导入时探测默认值并允许逐个图标覆盖，不得为整个图标集猜一个 tint。
- `pixelated` 只属于像素画且逐个图标设置；不得在渲染时推测，也不得应用于整个图标集。
- 项目图标通过共享的 `.oc-project-icon` 契约绘制，由 `--oc-project-icon-renderer` 选择；共享使用者必须询问 `opencard-app/src/shared/ui/visual/projectIconStyle.ts`，不得自行判断单个 renderer 取值。
- 一个文件夹只属于一个图标集：图标复制到 `<图标目录>/<集合 Key>/`，文件名严格等于图标 Key 加原扩展名；直接创建、导入图标包、以及从项目模板安装图标包必须产生同一种布局，不得把图标文件平铺写入图标目录根。
- 写入前必须解析该文件夹：更早的图标集留下的文件夹不得吸收新图标集的文件，因此给文件夹名加序号（`<集合 Key>-2`）而不是给内部文件名加序号；存在但不含文件的文件夹原样复用。
- 向已有图标集追加图标时，写入该集**现有的**文件所在文件夹（取自它已有图标的 `source`），不得按 Key 另开一个文件夹：集合可能已被改名，文件夹也可能带序号后缀。
- 追加图标时，新图标的引用名称必须避开目标集已有的 Key；排序、边界移动与批量命令都作用于当前选中集。
- 不得重新引入精灵表，也不得把独立图标合并成图集。
- 导入时每个文件只读取一次（探测 tint 与位图尺寸），并通过 `opencard-app/src/shared/async/mapWithConcurrency.ts` 并发探测。

## 兼容性

- 在当前测试版的领域模型和文件格式迁移中，新实现不为旧文件格式保留向后兼容逻辑。
