# 交互性能开发

约束见 [工程规则](./工程规则.md#交互性能)。本页说明现有实现中可以直接沿用的模式。

## 连续输入只改变视口

平移、缩放、滚动位置属于视图状态。它们不应触发文档解析、资源目录重建或项目文件扫描。持续位置输入复用 `src/utils/taskScheduler.ts`：

```ts
const dragInput = taskScheduler.frame((point: Point) => {
  viewportPosition.value = point
})

function move(point: Point) { dragInput.schedule(point) }
function finish() {
  dragInput.flush()
  commitGesture(viewportPosition.value)
}
onBeforeUnmount(() => dragInput.cancel())
```

`schedule` 在同一帧中覆盖旧位置；`flush` 保留松手前的最后一次输入；`cancel` 丢弃已销毁视图的输入。它适合位置采样，不能用于丢弃增量、文字输入或文件操作。

`CardViewport.vue` 的平移、选框拖拽和尺寸拖拽，以及 `useCdeViewportController.ts` 的预览导航共用这个入口。具有连续运动轨迹的缩放动画仍由自身的动画帧循环推进。

## 测量与投影分开

内容或布局变化后，集中读取几何数据；平移与缩放时使用已有坐标计算画面位置。不要在每次位置变化后等待 DOM 更新，再重新读取整份内容的边界。

`CardViewport.vue` 将选框保存为画布坐标，再根据平移与缩放计算视口坐标。修改文档、改变选中对象、容器尺寸变化仍会触发测量。

## 列表更新止于可见范围

结构索引负责父子关系、视觉顺序和键盘导航；滚动只读取可见范围及少量预渲染行。范围没有变化时，保留范围对象与行数组的引用。

共享 `OcTree` 负责窗口，内部 `OcTreeRow` 负责各行的响应式订阅。行的身份与所属上下文保持稳定，滚动进入一行不应使其余保留行的插槽全部重跑。动态资源和字段仍由对应行订阅，不能用忽略更新的缓存隐藏变化。

调用方复用 `OcTree` 的虚拟化能力，不自行再写一套窗口算法。菜单子项在菜单打开时解析，不能为了绘制列表提前生成所有子菜单。

## 后台结果有预算，也有归属

目录排序、差异和大型资源数据整理交给共享项目索引 Worker；主线程应用结果复用 `taskScheduler.runBatched` 或 `forEach`。每步只处理有界的数据，才能让每批 256 项、约 4ms 的预算生效。把一个巨大 `sort` 或 `JSON.parse` 放进单步回调仍会阻塞。

后台任务必须持有所属项目和请求的取消信号。先生成完整可用的新快照，确认请求仍有效后发布；失败保留旧快照。制作包、导出所需的全量扫描属于任务自身，不能扩大工作台缓存。

## 回归检查

- 工作量：同范围滚动不重复呈现；跨范围只新增进入视口的行；一帧多次位置输入只发布一次；平移不重新测量内容。
- 正确性：最后一次位置必须提交；取消、销毁、项目切换后不能发布旧结果；动态资源和键盘操作仍需正常更新。
- 实际耗时：分别记录开发版和生产版的逐帧间隔，以及脚本、布局、绘制成本。平均帧率和单元测试都不能替代实际帧耗时。

现有回归入口是 `OcTree.spec.ts`、`CardViewport.spec.ts`、`useCdeViewportController.spec.ts` 与项目资源、目录相关功能测试。扩展这些真实链路，避免另建绕过组件和索引的性能替身。

可复现页面为 `opencard-app/performance/interaction.html`，使用真实文件树、Worker 和 CDE，数据由页面生成，不读写用户项目。在应用目录运行开发服务后，打开 `/performance/interaction.html?files=100000`；将 `files` 改成 `10000` 可对照规模变化。

生产构建用 `npx vite build --config scripts/performance-vite-config.ts`，再用 `npx vite preview --outDir output/performance` 打开同一路径。页面记录每帧间隔、超预算帧、组件更新数量和输入发布耗时。输入发布耗时不包含所有后续绘制工作，不能当成整帧脚本或绘制耗时；此页面也不能代替原生目录、资源事件风暴和 Windows 桌面的综合验收。测量时不要同时运行构建、测试或热更新。
