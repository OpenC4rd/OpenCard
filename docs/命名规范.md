# OpenCard 命名规范

本规范适用于 OpenCard 仓库中的源码、测试、脚本、资源和项目自有代码符号。生态工具要求的固定名称与外部协议名称按本文例外处理。

## 基本原则

- 名称表达职责，不表达实现历史；避免 `new`、`old`、`v2`、`temp` 等阶段性后缀。
- 同一概念在文件名、导出符号和调用方中使用同一词汇。
- 命名整改不得顺带改变模块职责、持久化格式或公开协议。
- 项目自有缩写按普通单词处理；平台和第三方 API 保留其官方拼写。

## 目录与文件

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 源码目录 | kebab-case | `card-designer/` |
| Vue 组件 | PascalCase.vue | `PropertyEditor.vue` |
| TypeScript 模块 | lowerCamelCase.ts | `editorSessionStore.ts` |
| Composable | useXxx.ts | `useCdeLayerView.ts` |
| 类型专用模块 | lowerCamelCase.types.ts | `propertyEditor.types.ts` |
| 测试 | 与被测文件同名，可追加 lowerCamelCase 场景名；跨模块行为测试使用 lowerCamelCase；冻结契约的归档护栏追加 `.guard` | `editorSessionStore.autosave.spec.ts`、`workspacePages.spec.ts`、`OcCard.guard.spec.ts` |
| Rust 模块 | snake_case.rs | `file_watcher.rs` |
| 静态资源 | 小写 kebab-case | `opencard-logo-phase-map.png` |

以下名称按生态约定保留：

- `index.ts`、`main.ts`、`vite.config.ts`、`vite-env.d.ts`
- `package.json`、`tsconfig*.json`、`Cargo.toml`、`Cargo.lock`
- BCP 47 地区代码文件，例如 `zh-CN.ts`、`en-US.ts`
- 工具要求的隐藏目录和配置文件

`.types.ts` 用于“某主题的辅助类型集合”，尤其用于替代 `xxxTypes.ts` 这类容器名。以单一领域概念命名的契约模块可以保持 `editorIssue.ts`、`filePath.ts` 等概念名，即使当前实现只导出类型；不得仅根据是否产生运行时代码机械改名。

## 代码符号

- 类型、接口、类、枚举和 Vue 组件使用 PascalCase。
- 函数、变量、参数、属性和方法使用 lowerCamelCase。
- Composable 使用 `useXxx`。
- 只对真正的模块级常量使用 SCREAMING_SNAKE_CASE。
- OpenCard 品牌名始终写作 `OpenCard`。
- 项目自有缩写按单词处理：`Oc`、`Cde`、`QrCode`、`Css`、`Ui`、`Id`、`Url`。
- 平台和第三方名称保留官方拼写，例如 `HTMLElement`、`DOMRect`、`CSSProperties`、`JSON`、`URL`。

## Vue 与 CSS

- Vue 脚本中的 prop、emit 和 slot 名称使用 lowerCamelCase。
- 模板中的属性和事件使用 kebab-case，组件标签使用 PascalCase。
- CSS 类使用 kebab-case；结构类采用 BEM 的 `block__element--modifier` 形式。
- 状态类使用 `is-*` 或 `has-*`。
- 稳定 DOM 标记使用 `data-oc-*`，主题变量使用 `--oc-*`。

## 协议名称边界

下列名称属于数据或跨模块协议，不得由普通文件或符号重命名自动修改：

- `.ocdocument` 数据字段、`schemaVersion` 和类型判别值
- Tauri command 字符串及其他跨语言调用名称
- i18n key、图标 token、设置键和持久化存储键
- CSS 自定义属性、`data-oc-*` 属性和文件格式标识

协议名称如需调整，必须单独规划迁移、验证读写两端，并明确是否需要格式版本变化。

## 安全重命名流程

1. 先由命名审计生成明确违规项和人工确认项。
2. 只改真正违反本规范的名称；不为了统一风格批量重排既有名称。
3. 文件移动使用 `git mv`；TypeScript 引用由编辑器的重命名或语言服务计算。
4. 不对任意字符串字面量执行全局替换。
5. 每批完成后扫描旧名称，运行类型检查、测试和构建（`npm run verify`）。
6. 每批保持单一命名主题，能够独立审查和回滚。

## 自动化命令

在 `opencard-app` 目录运行：

```powershell
npm run audit:naming
npm run lint:naming
```

- `audit:naming` 生成非阻塞报告，`lint:naming` 对明确违规返回失败。
- Vue 模板符号需要 Vue Language Server 或经过逐项验证的边界修改，不得退化为全文替换。
- 协议名称（Tauri command 字符串、i18n key、CSS 自定义属性等）不参与机械重命名，见上一节。
