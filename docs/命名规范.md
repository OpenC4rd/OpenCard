# OpenCard 命名规范

适用于源码、测试、脚本、资源与项目自有符号。生态工具要求的固定名称与外部协议名称例外。

## 原则

- 名称表达职责，不表达实现历史（不出现 `new`、`old`、`v2`、`temp`）。
- 同一概念在文件名、导出符号与调用方用同一个词；项目自有缩写按单词处理（`Oc`、`Cde`、`QrCode`、`Css`、`Ui`、`Id`、`Url`），平台与第三方保留官方拼写。
- 命名整改不得顺带改变模块职责、持久化格式或公开协议。

## 目录与文件

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 源码目录 | kebab-case | `card-designer/` |
| Vue 组件 | PascalCase.vue | `PropertyEditor.vue` |
| TypeScript 模块 | lowerCamelCase.ts | `editorSessionManager.ts` |
| Composable | useXxx.ts | `useCdeLayerView.ts` |
| 类型专用模块 | lowerCamelCase.types.ts | `propertyEditor.types.ts` |
| 测试 | 与被测文件同名，可加 lowerCamelCase 场景名 | `editorSessionManager.autosave.spec.ts` |
| Rust 模块 | snake_case.rs | `file_watcher.rs` |
| 静态资源 | 小写 kebab-case | `opencard-logo-phase-map.png` |

保留生态名：`index.ts`、`main.ts`、`vite.config.ts`、`vite-env.d.ts`、`package.json`、`tsconfig*.json`、`Cargo.toml`、`Cargo.lock`、BCP 47 语言文件（`zh-CN.ts`）、工具要求的隐藏目录与配置。

`.types.ts` 用于"某主题的辅助类型集合"，替代 `xxxTypes.ts` 这类容器名。以单一领域概念命名的契约模块可用概念名（`editorIssue.ts`、`filePath.ts`），即使当前只导出类型；不要按"是否产生运行时代码"机械改名。

## 符号

- 类型、接口、类、枚举、组件 → PascalCase；函数、变量、参数、属性、方法 → lowerCamelCase；Composable → `useXxx`；只有真正的模块级常量用 SCREAMING_SNAKE_CASE。
- 品牌名始终写 `OpenCard`。

## Vue 与 CSS

- 脚本里的 prop、emit、slot 用 lowerCamelCase；模板属性与事件用 kebab-case；组件标签用 PascalCase。
- CSS 类 kebab-case，结构类用 BEM `block__element--modifier`；状态类用 `is-*` / `has-*`；稳定 DOM 标记用 `data-oc-*`；主题变量用 `--oc-*`。

## 协议名称边界

以下名称属于数据或跨模块协议，不得由普通重命名自动修改：`.ocdocument` 数据字段与类型判别值、Tauri command 字符串、i18n key、图标 token、设置键、持久化存储键、CSS 自定义属性、`data-oc-*`、文件格式标识。

协议名称调整必须单独规划迁移、验证读写两端，并明确是否需要格式版本变化。应用自有 i18n key 各层用 lowerCamelCase 并按业务归属划分命名空间，说明文案统一用 `description`；语言 key、DOM 定位标记、教程观看记录的身份各自维护，不因文案改名而联动。

## 安全重命名流程

1. 先由命名审计生成明确违规项与人工确认项。
2. 只改真正违规的名称，不为风格统一批量重排。
3. 文件移动用 `git mv`；引用由语言服务计算，不对任意字符串字面量全局替换。
4. 每批只做一个命名主题，完成后扫旧名、跑 `npm run verify`，可独立审查与回滚。
5. 协议名称（Tauri command、i18n key、CSS 变量等）不参与机械重命名。

## 自动化

在 `opencard-app` 下运行：`npm run audit:naming`（非阻塞报告）、`npm run lint:naming`（明确违规即失败）。Vue 模板符号需要 Vue Language Server 或逐项验证的边界修改。
